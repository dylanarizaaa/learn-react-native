## Introducción conceptual

Para ver tu app durante el desarrollo necesitas un binario instalado en el dispositivo que cargue tu JavaScript desde Metro. Hay dos opciones:

- <Term slug="expo-go">Expo Go</Term>: una app de las tiendas que ya incluye **todos los módulos del SDK de Expo**. Escaneas el QR y listo. No compila nada.
- **<Term slug="development-build">Development build</Term>**: **tu propia app** compilada en modo desarrollo con `expo-dev-client`. Incluye exactamente las librerías nativas que tu proyecto necesita, con tu nombre, icono y configuración.

La regla práctica: **Expo Go para aprender y prototipar; development build para cualquier app que vayas a publicar.**

## Ejemplo práctico

Convertir un proyecto en development build en tres pasos:

```bash
# 1. Añade el cliente de desarrollo
npx expo install expo-dev-client

# 2a. Compila en la nube con EAS (no necesitas Xcode ni Android Studio)
npm install -g eas-cli
eas build:configure
eas build --profile development --platform android

# 2b. …o compila en local si tienes el entorno nativo instalado
npx expo run:android
npx expo run:ios

# 3. Arranca Metro: el development build se conecta a él
npx expo start
```

El perfil `development` de `eas.json` define cómo se compila esa versión:

```json title="eas.json"
{
  "cli": { "version": ">= 27.0.0" },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "ios": { "simulator": true }
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}
```

## Explicación del código

- `expo-dev-client` añade una pantalla de inicio (*launcher*) para elegir a qué servidor de Metro conectarse, un menú de desarrollo mejorado e inspección de red.
- `developmentClient: true` indica que el binario es un development build. `distribution: "internal"` genera un archivo instalable directamente (APK en Android, o un build ad hoc o de simulador en iOS) sin pasar por la tienda.
- `"ios": { "simulator": true }` produce un build para el simulador de iOS, útil si no tienes cuenta de Apple Developer todavía.
- Una vez instalado, **solo recompilas cuando cambias dependencias nativas** o la configuración nativa (`app.json`, plugins). Los cambios de TypeScript se ven al instante con Fast Refresh.

## Buenas prácticas

- **Pasa a development build pronto** si sabes que publicarás la app: así pruebas desde el principio el mismo entorno que tendrás en producción.
- **Comparte el development build con tu equipo** mediante distribución interna para que nadie tenga que compilar.
- **Usa el fingerprint de Expo** (`npx expo-doctor` y el *fingerprint* de EAS) para saber si un cambio exige recompilar.

### Errores comunes

- Instalar una librería con código nativo (por ejemplo, un SDK de pagos) y probarla en Expo Go: fallará porque Expo Go no la incluye.
- Probar notificaciones push remotas en Expo Go en Android: desde SDK 53 requieren un development build.
- Crear un proyecto con el último SDK cuando Expo Go aún no lo soporta en las tiendas: durante la transición de SDK, la documentación oficial recomienda usar el SDK anterior si dependes de Expo Go en un dispositivo físico.

### Cuándo usar otra solución

Si solo quieres experimentar con un componente o compartir un ejemplo, [Expo Snack](https://snack.expo.dev) ejecuta código en el navegador y en Expo Go sin crear un proyecto local.
