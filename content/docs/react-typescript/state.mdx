## Introducción conceptual

El <Term slug="state">estado</Term> es la **memoria de un componente**: datos que cambian con el tiempo por acciones del usuario o por respuestas del sistema (un contador, el texto de un buscador, si un modal está abierto). Cuando el estado cambia, React **vuelve a ejecutar el componente** (un <Term slug="render">render</Term>) y actualiza la interfaz.

La interfaz es una función del estado: `UI = f(estado)`. No modificas la pantalla a mano; cambias el estado y React se encarga del resto.

### ¿Dónde debe vivir el estado?

En el **ancestro común más cercano** de los componentes que lo necesitan. Si dos hermanos necesitan el mismo dato, súbelo al padre (*lifting state up*) y pásalo con props.

## Ejemplo práctico

Un filtro de tareas que muestra los tres conceptos clave: estado mínimo, estado derivado e inmutabilidad.

```tsx title="src/app/tareas.tsx"
import { useState } from 'react';
import { FlatList, Pressable, StyleSheet, Text, View } from 'react-native';

type Task = { id: string; title: string; done: boolean };
type Filter = 'all' | 'pending' | 'done';

export default function TasksScreen() {
  // Estado mínimo: la lista y el filtro elegido
  const [tasks, setTasks] = useState<Task[]>([
    { id: '1', title: 'Diseñar la pantalla', done: true },
    { id: '2', title: 'Conectar la API', done: false },
    { id: '3', title: 'Escribir tests', done: false },
  ]);
  const [filter, setFilter] = useState<Filter>('all');

  // Estado derivado: se calcula, NO se guarda en otro useState
  const visible = tasks.filter((t) => (filter === 'all' ? true : filter === 'done' ? t.done : !t.done));
  const pendingCount = tasks.filter((t) => !t.done).length;

  function toggle(id: string) {
    // Inmutabilidad: creamos un array y un objeto nuevos
    setTasks((current) => current.map((t) => (t.id === id ? { ...t, done: !t.done } : t)));
  }

  return (
    <View style={styles.screen}>
      <Text style={styles.counter}>{pendingCount} pendientes</Text>
      <View style={styles.filters}>
        {(['all', 'pending', 'done'] as const).map((f) => (
          <Pressable key={f} onPress={() => setFilter(f)} style={[styles.chip, filter === f && styles.chipActive]}>
            <Text style={filter === f && styles.chipTextActive}>
              {f === 'all' ? 'Todas' : f === 'pending' ? 'Pendientes' : 'Hechas'}
            </Text>
          </Pressable>
        ))}
      </View>
      <FlatList
        data={visible}
        keyExtractor={(t) => t.id}
        renderItem={({ item }) => (
          <Pressable onPress={() => toggle(item.id)} style={styles.task}>
            <Text style={item.done && styles.done}>{item.title}</Text>
          </Pressable>
        )}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, padding: 16, gap: 12 },
  counter: { fontSize: 20, fontWeight: '700' },
  filters: { flexDirection: 'row', gap: 8 },
  chip: { paddingHorizontal: 12, paddingVertical: 6, borderRadius: 999, borderWidth: 1, borderColor: '#d1d5db' },
  chipActive: { backgroundColor: '#111827', borderColor: '#111827' },
  chipTextActive: { color: '#fff' },
  task: { paddingVertical: 14, borderBottomWidth: 1, borderColor: '#f3f4f6' },
  done: { textDecorationLine: 'line-through', color: '#9ca3af' },
});
```

## Explicación del código

- **Estado mínimo**: guardamos solo `tasks` y `filter`. La lista visible y el contador **se derivan** en cada render. Si los guardáramos en otro `useState`, tendríamos que mantenerlos sincronizados a mano y aparecerían errores.
- **Inmutabilidad**: `map` devuelve un array nuevo y `{ ...t, done: !t.done }` un objeto nuevo. React compara referencias para saber que algo cambió; si mutas el array original (`tasks[0].done = true`), la interfaz no se actualiza.
- **Actualización funcional** (`setTasks((current) => …)`) usa siempre el valor más reciente, importante si hay varias actualizaciones seguidas.
- **`as const`** hace que TypeScript trate el array como `readonly ['all', 'pending', 'done']`, así `f` tiene el tipo `Filter`.

## Buenas prácticas

- **Pregúntate si un dato es estado**: si se puede calcular a partir de props u otro estado, no lo es.
- **Agrupa estado relacionado** en un objeto si siempre cambia junto; sepáralo si cambia por separado.
- **Mantén el estado lo más local posible** y súbelo solo cuando otro componente lo necesite.
- **Distingue estado del servidor** (datos de la API, mejor con [TanStack Query](/docs/datos/tanstack-query)) de **estado del cliente** (UI, preferencias).

### Errores comunes

- Mutar arrays u objetos del estado (`push`, asignaciones directas).
- Copiar props en estado (`useState(props.value)`): el estado no se actualizará cuando cambie la prop.
- Esperar que el estado cambie inmediatamente después de llamar a `setState`: el nuevo valor estará disponible en el siguiente render.

### Cuándo usar otra solución

Cuando la lógica de actualización es compleja (muchas acciones que modifican el mismo estado), usa `useReducer`. Cuando el estado debe compartirse en toda la app, usa [Context](/docs/react-typescript/context-api) o [Zustand](/docs/arquitectura/estado-global-zustand).
