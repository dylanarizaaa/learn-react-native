## Descripción del proyecto

Técnicos que inspeccionan instalaciones en sótanos, zonas rurales o edificios sin cobertura necesitan una app que **funcione siempre**. En un diseño *offline-first*:

1. **La base de datos local es la fuente de verdad**: la UI lee y escribe en SQLite, nunca espera a la red.
2. **Cada cambio se registra en una cola (outbox)** en la misma transacción que el dato.
3. **Un motor de envío** procesa la cola cuando hay conexión, con reintentos y sin duplicar nada.

Este proyecto se centra en el **envío** de cambios locales al servidor. La recepción de cambios de otros dispositivos y la resolución de conflictos se tratan en [Sincronización de datos](/docs/proyectos/sincronizacion-de-datos).

```ts title="src/db/migrations.ts"
import type { SQLiteDatabase } from 'expo-sqlite';

export async function migrate(db: SQLiteDatabase) {
  const row = await db.getFirstAsync<{ user_version: number }>('PRAGMA user_version');
  if ((row?.user_version ?? 0) >= 1) return;
  await db.execAsync(`
    PRAGMA journal_mode = WAL;
    CREATE TABLE inspections (
      id TEXT PRIMARY KEY,               -- UUID generado en el dispositivo
      site TEXT NOT NULL,
      result TEXT NOT NULL CHECK (result IN ('ok', 'observation', 'failure')),
      notes TEXT NOT NULL DEFAULT '',
      updated_at INTEGER NOT NULL,
      sync_state TEXT NOT NULL DEFAULT 'pending' -- 'pending' | 'synced' | 'error'
    );
    CREATE TABLE photos (
      id TEXT PRIMARY KEY,
      inspection_id TEXT NOT NULL REFERENCES inspections (id) ON DELETE CASCADE,
      file_name TEXT NOT NULL,           -- relativo a Paths.document
      uploaded INTEGER NOT NULL DEFAULT 0
    );
    CREATE TABLE outbox (
      seq INTEGER PRIMARY KEY AUTOINCREMENT, -- orden de envío
      kind TEXT NOT NULL,                    -- 'upsert-inspection' | 'upload-photo'
      entity_id TEXT NOT NULL,
      payload TEXT NOT NULL,
      idempotency_key TEXT NOT NULL UNIQUE,
      attempts INTEGER NOT NULL DEFAULT 0,
      next_attempt_at INTEGER NOT NULL DEFAULT 0,
      last_error TEXT
    );
    PRAGMA user_version = 1;
  `);
}
```

<Step title="Escribir el dato y la intención en la misma transacción">

```ts title="features/inspections/repository.ts"
import { randomUUID } from 'expo-crypto';
import type { SQLiteDatabase } from 'expo-sqlite';

export type Inspection = { id: string; site: string; result: 'ok' | 'observation' | 'failure'; notes: string; updatedAt: number };

export const inspectionsRepository = {
  /** Guarda localmente y encola el envío. Nunca toca la red. */
  async save(db: SQLiteDatabase, input: Omit<Inspection, 'id' | 'updatedAt'> & { id?: string }) {
    const inspection: Inspection = { ...input, id: input.id ?? randomUUID(), updatedAt: Date.now() };

    await db.withExclusiveTransactionAsync(async (tx) => {
      await tx.runAsync(
        `INSERT INTO inspections (id, site, result, notes, updated_at, sync_state) VALUES (?, ?, ?, ?, ?, 'pending')
         ON CONFLICT (id) DO UPDATE SET site = excluded.site, result = excluded.result, notes = excluded.notes,
           updated_at = excluded.updated_at, sync_state = 'pending'`,
        inspection.id, inspection.site, inspection.result, inspection.notes, inspection.updatedAt,
      );
      // Si ya había un envío pendiente de esta inspección, lo sustituimos por el más reciente
      await tx.runAsync(`DELETE FROM outbox WHERE kind = 'upsert-inspection' AND entity_id = ?`, inspection.id);
      await tx.runAsync(
        `INSERT INTO outbox (kind, entity_id, payload, idempotency_key) VALUES ('upsert-inspection', ?, ?, ?)`,
        inspection.id, JSON.stringify(inspection), `${inspection.id}:${inspection.updatedAt}`,
      );
    });
    return inspection;
  },

  list(db: SQLiteDatabase) {
    return db.getAllAsync<Inspection & { syncState: string }>(
      'SELECT id, site, result, notes, updated_at AS updatedAt, sync_state AS syncState FROM inspections ORDER BY updated_at DESC',
    );
  },
};
```

<Step title="El motor de envío con reintentos">

```ts title="features/offline/sync-engine.ts"
import NetInfo from '@react-native-community/netinfo';
import { File, Paths } from 'expo-file-system';
import type { SQLiteDatabase } from 'expo-sqlite';
import { api } from '@/lib/api-client';
import { useSyncStore } from './sync-store';

type OutboxRow = { seq: number; kind: string; entity_id: string; payload: string; idempotency_key: string; attempts: number };

const MAX_BACKOFF = 5 * 60_000;
let running = false;

async function send(row: OutboxRow) {
  const headers = { 'Idempotency-Key': row.idempotency_key }; // el servidor ignora repeticiones
  if (row.kind === 'upsert-inspection') {
    await api.put(`/inspections/${row.entity_id}`, JSON.parse(row.payload), { headers });
  } else if (row.kind === 'upload-photo') {
    const { inspectionId, fileName } = JSON.parse(row.payload) as { inspectionId: string; fileName: string };
    const file = new File(Paths.document, 'photos', fileName);
    const form = new FormData();
    form.append('photo', { uri: file.uri, name: fileName, type: 'image/jpeg' } as unknown as Blob);
    await api.post(`/inspections/${inspectionId}/photos`, form, { headers });
  }
}

/** Procesa la cola en orden. Se detiene ante el primer error para respetar el orden de los cambios. */
export async function processOutbox(db: SQLiteDatabase) {
  if (running) return;
  const net = await NetInfo.fetch();
  if (!net.isConnected) return;

  running = true;
  useSyncStore.getState().setSyncing(true);
  try {
    while (true) {
      const row = await db.getFirstAsync<OutboxRow>('SELECT * FROM outbox WHERE next_attempt_at <= ? ORDER BY seq LIMIT 1', Date.now());
      if (!row) break;
      try {
        await send(row);
        await db.withExclusiveTransactionAsync(async (tx) => {
          await tx.runAsync('DELETE FROM outbox WHERE seq = ?', row.seq);
          if (row.kind === 'upsert-inspection') {
            // Solo marcamos como sincronizada si no hay otro cambio más nuevo en cola
            await tx.runAsync(
              `UPDATE inspections SET sync_state = 'synced' WHERE id = ? AND NOT EXISTS (SELECT 1 FROM outbox WHERE entity_id = ?)`,
              row.entity_id, row.entity_id,
            );
          }
        });
      } catch (error) {
        const attempts = row.attempts + 1;
        const delay = Math.min(MAX_BACKOFF, 2 ** attempts * 1000);
        await db.runAsync('UPDATE outbox SET attempts = ?, next_attempt_at = ?, last_error = ? WHERE seq = ?',
          attempts, Date.now() + delay, String(error), row.seq);
        break; // reintentaremos más tarde
      }
    }
  } finally {
    running = false;
    const pending = await db.getFirstAsync<{ n: number }>('SELECT COUNT(*) AS n FROM outbox');
    useSyncStore.getState().update({ syncing: false, pending: pending?.n ?? 0, lastRunAt: Date.now() });
  }
}
```

<Step title="Disparar el envío: red, arranque y primer plano">

```ts title="features/offline/use-sync-triggers.ts"
import NetInfo from '@react-native-community/netinfo';
import { useSQLiteContext } from 'expo-sqlite';
import { useEffect } from 'react';
import { AppState } from 'react-native';
import { processOutbox } from './sync-engine';

export function useSyncTriggers() {
  const db = useSQLiteContext();

  useEffect(() => {
    processOutbox(db); // al arrancar

    const netSub = NetInfo.addEventListener((state) => {
      if (state.isConnected) processOutbox(db); // al recuperar la red
    });
    const appSub = AppState.addEventListener('change', (s) => {
      if (s === 'active') processOutbox(db); // al volver a primer plano
    });
    const interval = setInterval(() => processOutbox(db), 60_000); // reintentos programados

    return () => {
      netSub();
      appSub.remove();
      clearInterval(interval);
    };
  }, [db]);
}
```

<Callout type="info" title="Fotos sin conexión">
Al hacer una foto, `photos.ts` copia el archivo temporal a `Paths.document/photos` (ver [Expo FileSystem](/docs/expo/expo-file-system)), guarda solo el **nombre** del archivo en la tabla `photos` y encola un `upload-photo` en la misma transacción. Guardar rutas relativas evita problemas cuando el contenedor de la app cambia de ruta en iOS.
</Callout>

## Qué has aprendido

- **Local como fuente de verdad**: la UI nunca espera a la red.
- **Patrón outbox**: el dato y la intención de enviarlo se guardan en la misma transacción, así nunca se pierde un cambio.
- **Idempotencia**: los reintentos no crean duplicados gracias a la `Idempotency-Key` (el backend debe respetarla).
- **Reintentos con backoff** persistidos en la base de datos, que sobreviven a cierres de la app.
- **Disparadores** de envío: arranque, recuperación de red, primer plano y temporizador.
