## Introducción conceptual

Antes de escribir el primer componente, necesitamos una base sólida: el proyecto Expo, NativeWind funcionando, una utilidad para combinar clases y los **tokens de diseño** con soporte de modo oscuro. Este tema reúne todos esos pasos en el orden correcto; los detalles de cada archivo de NativeWind están explicados en [Configuración de NativeWind](/docs/estilos/configuracion-de-nativewind).

```tsx title="src/theme/theme-provider.tsx"
import type { ReactNode } from 'react';
import { View } from 'react-native';
import { useColorScheme } from 'nativewind';
import { themeVars } from './tokens';

export function ThemeProvider({ children }: { children: ReactNode }) {
  const { colorScheme } = useColorScheme();
  return (
    <View style={themeVars[colorScheme === 'dark' ? 'dark' : 'light']} className="flex-1 bg-background">
      {children}
    </View>
  );
}
```

import { clsx, type ClassValue } from 'clsx';

export function cn(...inputs: ClassValue[]) {

}

## Explicación del código

- **`token(name)`** genera colores que leen variables CSS. Los componentes solo usan nombres semánticos (`bg-primary`, `text-muted-foreground`); los valores reales viven en `tokens.ts`.
- **`const dark: typeof light`** obliga a que el tema oscuro defina exactamente las mismas variables: si añades un token a `light` y lo olvidas en `dark`, TypeScript lo detecta.
- **`ThemeProvider`** aplica las variables del esquema actual a un `View` raíz; todos los descendientes heredan los valores.
- **`darkMode: 'class'`** permite cambiar el esquema desde la app (con `setColorScheme` de NativeWind), como vimos en [Dark Mode](/docs/estilos/dark-mode).
- **`cn()`** es la utilidad que usarán todos los componentes: combina clases condicionales y resuelve conflictos (`px-4` del componente frente a `px-2` del consumidor).
- **`GestureHandlerRootView`** queda preparado para el Sheet con gestos y otros componentes interactivos.

## Buenas prácticas

- **Commitea la configuración completa** y documenta en el README el comando `npx expo start --clear` tras cambios en Babel o Metro.
- **Mantén pocos tokens** al principio; añade nuevos solo cuando un componente lo necesite de verdad.
- **Prueba ambos modos** desde el primer componente.

### Errores comunes

- Instalar `tailwindcss` v4 con NativeWind v4: usa `tailwindcss@^3.4`.
- Valores de tokens en hexadecimal: con el formato `R G B` funcionan los modificadores de opacidad (`bg-primary/10`).
- Olvidar envolver la app con `ThemeProvider`: los colores semánticos no tendrán valor.

### Cuándo usar otra solución

Si tu proyecto ya existe con StyleSheet, puedes adoptar NativeWind de forma gradual: ambos conviven sin problemas. Revisa los criterios en [NativeWind vs StyleSheet](/docs/sistema-de-componentes/nativewind-vs-stylesheet).
