## Introducción conceptual

En esta sección construimos, paso a paso, un **kit de componentes** propio para apps Expo: el tipo de biblioteca que las empresas tienen internamente y que hace que cada pantalla nueva sea rápida de construir y consistente. Al terminar tendrás:

- Un proyecto **Expo SDK 58 + TypeScript + NativeWind v4** configurado.
- **Tokens de diseño** con modo claro/oscuro y variantes tipadas con `cva`.
- Componentes listos para producción: **Button, Input, Card, Modal/Sheet, Select, Form**, componentes de navegación, carga y estados vacíos.
- Patrones de **composición** y de **separación entre lógica y presentación**.
- Una **biblioteca compartida** en un monorepo, reutilizable entre proyectos.

### Principios del kit

<Columns>
  <Column title="Diseño" tone="brand">
    - Solo **tokens semánticos** (`bg-primary`, `text-muted-foreground`).
    - **Variantes tipadas** con `cva`: `variant` y `size`.
    - Modo oscuro desde el primer componente.
  </Column>
  <Column title="Ingeniería">
    - **Props nativas extendidas** (`PressableProps`, `TextInputProps`).
    - **Accesibilidad por defecto**: roles, estados, etiquetas.

  </Column>
</Columns>

## Ejemplo práctico

Así se verá una pantalla construida con el kit terminado. Fíjate en que no hay ni un color literal ni un estilo repetido:

```tsx title="src/app/(auth)/login.tsx"
import { Link } from 'expo-router';
import { View } from 'react-native';
import { SafeAreaView } from 'react-native-safe-area-context';
import { Button, Card, Text } from '@/components/ui';
import { FormInput } from '@/components/form';
import { useLoginForm } from '@/features/auth/hooks/use-login-form';

export default function LoginScreen() {
  const { control, submit, isSubmitting } = useLoginForm();

  return (
    <SafeAreaView className="flex-1 justify-center bg-background p-6">
      <Card>
        <Card.Header>
          <Card.Title>Bienvenido de nuevo</Card.Title>
          <Card.Description>Inicia sesión para continuar</Card.Description>
        </Card.Header>
        <Card.Content className="gap-4">
          <FormInput control={control} name="email" label="Email" inputMode="email" autoComplete="email" />
          <FormInput control={control} name="password" label="Contraseña" secureTextEntry autoComplete="current-password" />
        </Card.Content>
        <Card.Footer className="flex-col items-stretch gap-3 border-t-0">
          <Button onPress={submit} loading={isSubmitting} fullWidth>
            Entrar
          </Button>
          <View className="flex-row justify-center gap-1">
            <Text variant="caption">¿No tienes cuenta?</Text>
            <Link href="/registro">
              <Text variant="caption" tone="primary">
                Regístrate
              </Text>
            </Link>
          </View>
        </Card.Footer>
      </Card>
    </SafeAreaView>
  );
}
```

## Explicación del código

- **`Card` con subcomponentes** (`Card.Header`, `Card.Title`…) es composición: la pantalla decide la estructura y la tarjeta aporta el estilo.
- **`FormInput`** conecta un `Input` del kit con React Hook Form: etiqueta, error de validación y accesibilidad incluidos.
- **`Button` con `loading` y `fullWidth`**: variantes y estados que cualquier pantalla necesita, resueltos una vez.
- **`useLoginForm`** contiene la lógica (esquema de Zod, envío, errores del servidor). La pantalla solo describe la interfaz.
- **`bg-background`** es un token: cambia automáticamente en modo oscuro.

## Buenas prácticas

- **Sigue la sección en orden**: cada componente reutiliza los anteriores (`Select` usa `Sheet`, los formularios usan `Input` y `Select`).
- **Crea una ruta de catálogo** en desarrollo para ver todos los componentes y variantes juntos.
- **Adapta los tokens a tu marca**, no los componentes.

### Errores comunes

- Saltar directamente a los componentes sin configurar tokens: acabarás con colores literales por todas partes.
- Copiar el kit sin entender las decisiones: cada tema explica el porqué para que puedas adaptarlo.

### Cuándo usar otra solución

Si necesitas una UI completa de inmediato, existen kits de la comunidad basados en NativeWind con filosofía similar a shadcn/ui. Construir el tuyo te da control total y entendimiento profundo; usar uno existente te da velocidad. Este curso te prepara para ambas opciones.
