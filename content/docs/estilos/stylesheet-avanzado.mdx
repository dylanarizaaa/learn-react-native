## Introducción conceptual

Más allá de `StyleSheet.create`, un proyecto profesional necesita resolver varias situaciones: **diferencias entre plataformas**, **estilos que dependen del tema**, **composición** de estilos recibidos por props y aprovechar las **nuevas propiedades visuales** que llegaron con la Nueva Arquitectura (sombras CSS, filtros, contornos, modos de fusión).

## Ejemplo práctico

Una fábrica de estilos tematizada, con detalles por plataforma y las propiedades modernas:

```tsx title="src/theme/make-styles.ts"
import { useMemo } from 'react';
import { StyleSheet, useColorScheme } from 'react-native';

export const palette = {
  light: { background: '#ffffff', surface: '#f8fafc', text: '#0f172a', muted: '#64748b', primary: '#0284c7', border: '#e2e8f0' },
  dark: { background: '#0b1120', surface: '#111827', text: '#f1f5f9', muted: '#94a3b8', primary: '#38bdf8', border: '#1f2937' },
} as const;

export type Theme = { colors: (typeof palette)['light']; dark: boolean };

/** Crea un hook que genera estilos a partir del tema, memoizados por esquema de color. */
export function makeStyles<T extends StyleSheet.NamedStyles<T>>(factory: (theme: Theme) => T) {
  return function useStyles() {
    const scheme = useColorScheme() === 'dark' ? 'dark' : 'light';
    return useMemo(() => StyleSheet.create(factory({ colors: palette[scheme], dark: scheme === 'dark' })), [scheme]);
  };
}
```

```tsx title="src/components/feature-card.tsx"
import { Platform, Pressable, Text, View, type StyleProp, type ViewStyle } from 'react-native';
import { makeStyles } from '@/theme/make-styles';

type FeatureCardProps = { title: string; description: string; disabled?: boolean; style?: StyleProp<ViewStyle> };

export function FeatureCard({ title, description, disabled, style }: FeatureCardProps) {
  const styles = useStyles();
  return (
    <Pressable
      disabled={disabled}
      style={({ pressed, focused }) => [
        styles.card,
        pressed && styles.pressed,
        focused && styles.focused, // teclado/lector de pantalla
        disabled && styles.disabled,
        style, // los estilos del padre van al final: pueden sobrescribir
      ]}
    >
      <View style={styles.badge} />
      <Text style={styles.title}>{title}</Text>
      <Text style={styles.description}>{description}</Text>
    </Pressable>
  );
}

const useStyles = makeStyles(({ colors, dark }) => ({
  card: {
    padding: 18,
    gap: 6,
    borderRadius: 18,
    backgroundColor: colors.surface,
    borderWidth: 1,
    borderColor: colors.border,
    boxShadow: dark ? 'none' : '0 6px 20px rgba(15, 23, 42, 0.08)',
    ...Platform.select({
      ios: { borderCurve: 'continuous' as const }, // esquinas "squircle" de iOS
      default: {},
    }),
  },
  pressed: { transform: [{ scale: 0.98 }] },
  focused: { outlineWidth: 2, outlineColor: colors.primary, outlineOffset: 2 },
  disabled: { filter: 'grayscale(1)', opacity: 0.6 },
  badge: { width: 28, height: 4, borderRadius: 2, backgroundColor: colors.primary },
  title: { fontSize: 17, fontWeight: '600', color: colors.text },
  description: { fontSize: 14, lineHeight: 20, color: colors.muted },
}));
```

## Explicación del código

- **`makeStyles`** recibe una función que devuelve estilos a partir del tema y produce un hook. Gracias a `useMemo`, `StyleSheet.create` solo se ejecuta cuando cambia el esquema de color, no en cada render.
- **`NamedStyles<T>`** mantiene el autocompletado y la validación de tipos de cada estilo.
- **`Platform.select`** devuelve el valor de la plataforma actual (`ios`, `android`, `web` o `default`). **`borderCurve: 'continuous'`** solo existe en iOS y da esquinas más suaves.
- **`focused`** en el estilo de `Pressable` permite dibujar un anillo de foco para navegación con teclado o lectores de pantalla; **`outline*`** no ocupa espacio en el layout.
- **`filter: 'grayscale(1)'`** desatura el contenido de forma nativa (sin imágenes duplicadas).
- **`style` del padre al final del array**: el consumidor del componente puede ajustar márgenes o anchos sin tocar el componente.

### Archivos por plataforma

Si un componente difiere mucho entre plataformas, separa la implementación. Metro elige el archivo según la plataforma:

```tree
src/components/
  date-input.ios.tsx # Selector nativo de iOS
  date-input.android.tsx # Diálogo de Android
  date-input.tsx # Web (o implementación por defecto)
```

## Buenas prácticas

- **Una fuente de tokens** (colores, radios, espaciados) y estilos que la consumen; nunca colores literales repetidos.
- **Acepta `style` en tus componentes** reutilizables y aplícalo al final.
- **Usa `StyleSheet.flatten` solo si necesitas leer un valor** (por ejemplo, el color de un estilo recibido); para aplicar estilos, los arrays bastan.
- **Prefiere `boxShadow`** a la combinación antigua `shadow*` + `elevation`: un solo valor, igual en ambas plataformas.

### Errores comunes

- Crear estilos con `StyleSheet.create` dentro del cuerpo del componente sin memoizar: se recrean en cada render.
- Usar `elevation` y `shadowColor` y obtener sombras distintas en cada plataforma.
- Usar `zIndex` para corregir un orden de dibujado que se arregla reordenando los hijos.

### Cuándo usar otra solución

Si tu equipo prefiere clases utilitarias y quiere variantes y modo oscuro sin fábricas propias, usa [NativeWind](/docs/estilos/nativewind). Comparamos ambos enfoques en [NativeWind vs StyleSheet](/docs/sistema-de-componentes/nativewind-vs-stylesheet).
