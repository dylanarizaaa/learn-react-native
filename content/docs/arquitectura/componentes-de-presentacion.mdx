## Introducción conceptual

Un **componente de presentación** se ocupa de **cómo se ven las cosas**. Recibe todo lo que necesita por props, avisa de las interacciones mediante callbacks y no sabe de dónde vienen los datos: ni APIs, ni stores, ni navegación.

Es el equivalente visual de una función pura: **mismas props, misma interfaz**. Esa propiedad los hace fáciles de reutilizar, de testear y de previsualizar con datos inventados.

## Ejemplo práctico

Una tarjeta de pedido puramente visual, con su test:

```tsx title="src/features/orders/components/order-card.tsx"
import { Pressable, Text, View } from 'react-native';
import type { OrderStatus } from '../types';

export type OrderCardProps = {
  number: string;
  customerName: string;
  itemsCount: number;
  total: string; // ya formateado: la tarjeta no decide la moneda
  status: OrderStatus;
  onPress: () => void;
  onCancel?: () => void;
};

const STATUS: Record<OrderStatus, { label: string; className: string }> = {
  pending: { label: 'Pendiente', className: 'bg-amber-100 text-amber-800' },
  paid: { label: 'Pagado', className: 'bg-emerald-100 text-emerald-800' },
  shipped: { label: 'Enviado', className: 'bg-sky-100 text-sky-800' },
  cancelled: { label: 'Cancelado', className: 'bg-zinc-200 text-zinc-600' },
};

export function OrderCard({ number, customerName, itemsCount, total, status, onPress, onCancel }: OrderCardProps) {
  const badge = STATUS[status];
  return (
    <Pressable
      onPress={onPress}
      accessibilityRole="button"
      accessibilityLabel={`Pedido ${number} de ${customerName}, ${badge.label}, total ${total}`}
      className="gap-2 rounded-2xl border border-zinc-200 bg-white p-4 active:opacity-80"
    >
      <View className="flex-row items-center justify-between">
        <Text className="font-semibold">Pedido #{number}</Text>
        <Text className={`rounded-full px-2 py-0.5 text-xs font-semibold ${badge.className}`}>{badge.label}</Text>
      </View>
      <Text className="text-zinc-500">
        {customerName} · {itemsCount} {itemsCount === 1 ? 'artículo' : 'artículos'}
      </Text>
      <View className="flex-row items-center justify-between">
        <Text className="text-lg font-bold">{total}</Text>
        {onCancel && status === 'pending' ? (
          <Pressable onPress={onCancel} hitSlop={8} accessibilityRole="button">
            <Text className="font-medium text-red-600">Cancelar</Text>
          </Pressable>
        ) : null}
      </View>
    </Pressable>
  );
}
```

```tsx title="src/features/orders/components/order-card.test.tsx"
import { render, screen, userEvent } from '@testing-library/react-native';
import { OrderCard } from './order-card';

const baseProps = {
  number: '1042',
  customerName: 'Ana Pérez',
  itemsCount: 3,
  total: '$45.900',
  status: 'pending' as const,
};

test('muestra el resumen y permite cancelar un pedido pendiente', async () => {
  const user = userEvent.setup();
  const onCancel = jest.fn();
  await render(<OrderCard {...baseProps} onPress={jest.fn()} onCancel={onCancel} />);

  expect(screen.getByText('Pedido #1042')).toBeOnTheScreen();
  expect(screen.getByText('Pendiente')).toBeOnTheScreen();

  await user.press(screen.getByRole('button', { name: 'Cancelar' }));
  expect(onCancel).toHaveBeenCalledTimes(1);
});

test('no muestra la acción de cancelar en pedidos enviados', async () => {
  await render(<OrderCard {...baseProps} status="shipped" onPress={jest.fn()} onCancel={jest.fn()} />);
  expect(screen.queryByText('Cancelar')).not.toBeOnTheScreen();
});
```

## Explicación del código

- **`total` llega formateado** como string. La tarjeta no decide moneda ni idioma: eso es responsabilidad de quien prepara los datos.
- **`onCancel` es opcional**: si el contenedor no permite cancelar, no lo pasa y el botón no aparece. La tarjeta no consulta permisos.
- **El mapa `STATUS`** contiene clases completas (no construidas dinámicamente) para que Tailwind las genere.
- **`accessibilityLabel`** resume toda la tarjeta para los lectores de pantalla.
- **El test** no necesita mocks de red, stores ni navegación: renderiza con props y comprueba lo que ve el usuario. En React Native Testing Library 14, `render` es asíncrono (`await render(...)`).

## Buenas prácticas

- **Props de datos ya preparadas** (formateadas, filtradas) desde el contenedor o el hook.
- **Callbacks con nombres de intención** (`onCancel`, `onSelectProduct`) en lugar de detalles de implementación (`onButtonPress`).
- **Crea variantes de ejemplo** (pendiente, enviado, cancelado) en un catálogo o Storybook para revisar el diseño sin la app completa.

### Errores comunes

- Importar `useRouter` o un store "por comodidad": el componente deja de ser reutilizable.
- Pasar el objeto completo de la API cuando solo se necesitan tres campos: acopla la UI a la forma de la respuesta.

### Cuándo usar otra solución

No todo tiene que ser presentacional: un `SearchBar` con su propio *debounce* o un `Select` con su lista desplegable pueden tener estado interno de UI. Lo importante es que no dependan de datos externos. Los datos llegan desde [componentes contenedores](/docs/arquitectura/componentes-contenedores) o hooks.
